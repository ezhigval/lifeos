## 1. Формы «Планируемый доход / расход» — обязательные поля (BUG)
**Симптом:** даже когда все видимые поля заполнены, форма требует «внести все поля» —
валидация не проходит / скрытые обязательные поля не подсвечиваются.
**Ожидаемо:** сабмит проходит при заполненных видимых полях; недостающие обязательные поля
явно показаны и валидируются на клиенте ДО запроса; серверная валидация возвращает понятные ошибки.
**Зоны:** Frontend (sheet/form finance planned), Backend (validation contract, OpenAPI).
**Acceptance:** e2e-сценарий «создать планируемый расход» и «планируемый доход» проходит с нуля
без ручного догадывания о скрытых полях; тест на контракт ошибок валидации.

## 2. Главная не отображает задачи (BUG)
**Симптом:** блок «Задачи» на главной пуст, хотя задачи есть.
**Диагностика:** проверить query-key/фильтры list-tasks (context, date-range, status),
response shape vs expectations клиента, регрессию после TASK-005/MA-* изменений.
**Acceptance:** на главной видны сегодняшние+просроченные задачи; добавлен frontend-тест/
mock-API-контракт; причина бага задокументирована в отчёте.

## 3. Трекер привычек — edit / delete / срок (FEATURE-P0)
- Редактирование привычки (название, расписание, иконка/цвет).
- Удаление привычки (с подтверждением; история трекинга — soft/cascade по решению backend).
- **Срок habit'а:** start_date / end_date (или «бессрочно»), прогресс в пределах срока.
**Backend:** PATCH/DELETE `/habits/{id}`, поля `start_date,end_date` (миграция).
**Frontend:** экран привычки → меню Edit/Delete, поле срока в форме создания.
**Telegram:** команды/FSM для edit/delete при наличии мини-формы (P1, не блокирует).

## 4. Календарь — виды месяц/неделя/день + фильтры (FEATURE-P0)
- Переключатель видов **Month / Week / Day** (как iOS Calendar).
- В любом виде отображаются ВСЕ доменные сущности с датами: события, задачи (due), напоминания.
- Фильтры: по **воркспейсам** (когда появятся WS — см. TASK-010; сейчас: «личное») и по **сферам**.
**Backend:** единый endpoint `/calendar/aggregate?from&to&views` (или расширение текущего) —
отдача tagged items {type,id,date,title,color,context}.
**Frontend:** компонент календаря с 3 режимами + bottom-sheet фильтров.

## 5. Заметки и напоминания — двусторонняя синхронизация + привязка (FEATURE-P0)
- Создал заметку/напоминание **из задачи** → она появляется в общих списках «Заметки»/«Напоминания»
  с бейджем связи («← задача …») и открывает задачу по тапу.
- Создаю заметку/напоминание **из своего меню** → выбор привязки через каскадную подсказку
  **воркспейс → сфера → проект → задача** (autocomplete, любой уровень опционален).
- Отвязка/смена привязки из карточки заметки/напоминания.
**Backend:** связь note↔task / reminder↔task (nullable FK сейчас; polymorphic targets придут с WS-12);
list endpoints отдают linked entity summary.
**Frontend:** каскадный picker (ws→sphere→project→task) переиспользуемый; бейджи и переходы.

## 6. Настройки — что показывать на главной (FEATURE-P0)
- Тоуглы видимости блоков главной: **задачи, трекер привычек, финансы, заметки, календарь,
  напоминания, долги** (+ порядок drag-nick если дёшево, иначе up/down).
- Хранение per-user (settings domain уже существует — расширить key `home.layout`).
**Acceptance:** выключенный блок не рендерится и не запрашивает данные (экономия запросов).

## 7. Задачи — привязка к нескольким сферам/проектам (FEATURE-P0, сейчас — в рамках личного)
- **Уже частично есть:** `task_projects` (миграция 00023) + `EditTaskInput.ProjectIDs` +
  `attachProjects` — backend N:M для ПРОЕКТОВ реализован ранее. Не хватает:
  1) мультивыбора в форме задачи на FE (чипы + autocomplete, показ всех привязок в карточке);
  2) N:M для СФЕР — новая таблица `task_spheres(task_id, sphere_id)` (миграция), фильтры
     list-tasks/календарь/статистика должны учитывать все связи (сейчас только основная `sphere_id`).
- Основная связь `project_id` сохраняется для обратной совместимости; удаление связи не удаляет задачу.
**Acceptance:** задача «Подготовить отчёт по зарплатам» видна одновременно в сферах «Деньги»
и «Карьера» и в обоих выбранных проектах; тест на миграцию `task_spheres` и фильтры.

## 8. Сфера «Деньги» → Финансы: автогенерация planned-записей (FEATURE-P0, личная версия)
- До воркспейсов (TASK-010/WS-15) реализуется personal-версия правила: проект сферы «Деньги»
  с меткой/названием «Зарплата» + задача вида «зарплата <Имя> <сумма>» → при сохранении задачи
  создаётся/обновляется **планируемый доход** «Зарплата — <Имя> — сумма» (идемпотентно по
  `origin_task_id`; при удалении задачи зеркало убирается).
- Парсинг суммы из названия задачи — эвристикой + подтверждаемое поле в форме («Сумма зарплаты»).
- Механизм закладывается как `domain_rule engine` (реестр правил), чтобы WS-15 подключил
  money→expense-in-ws и health→habits без переписывания.
**Acceptance:** e2e: создал задачу «зарплата Иван 100000» в проекте «Зарплата» → в planned-доходах
появилась запись 100 000; удалил задачу → записи нет; повторное сохранение не дублирует.
