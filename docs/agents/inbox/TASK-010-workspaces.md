# TASK-010 — Shared Workspaces (шерированные сферы)

**Приоритет:** P1 (новая эпикa) · **Статус:** DRAFT (Architect переведёт в OPEN после закрытия P0)
**Врата запуска:** старт **строго после** закрытия P0-багов dogfood (`TASK-008-dogfood-p0`).

## Проблема

Сейчас LifeOS — персональный ассистент: все данные (задачи, финансы, календарь, заметки)
привязаны к одному пользователю. Нужно поддерживать **общие воркспейсы** (например «Бизнес»):
сотрудники, своя экономика, календарь, задачи, заметки — изолированно от личного,
но с контролем смешивания на главной.

## Требования

### 1. Сфера = воркспейс (шаринг)
- `life_spheres` получает флаг шеринга + владельцев/участников (`workspaces`, `workspace_members`, роли owner/editor/viewer).
- Сотрудники — участники воркспейса; у каждого свои задачи внутри воркспейса.

### 2. Отдельные домены в контексте воркспейса
- Задачи, экономика (доходы/расходы/планируемые), календарь, заметки, долги, привычки, аналитика —
  всё имеет `workspace_id` (NULL = личное). Внутри воркспейса видно **все дела всех участников**.

### 3. Главная: подмешивание и экраны
- Сегменты на главной: **«Все / Личное / Воркспейсы»** (+ выбор конкретного ws).
- В «Всех» показываются только **мои** личные + **мои** задачи/события из воркспейсов
  (чужие задачи сотрудников там не видны).
- В экране конкретного ws — всё, включая дела других участников.
- Настройки: **какие домены отображаются на главной** (задачи, трекер привычек, финансы,
  заметки, календарь, напоминания, долги — вкл/выкл + порядок блоков) и какие
  воркспейсы подмешивать. *(owner 2026-07-19)*

### 4. Финансовая синхронизация (cross-context)
- Назначаю в воркспейсе планируемый расход «зарплата → сотруднику X», где X — это я:
  в личном контексте появляется зеркало «планируемый доход — зарплата — сумма».
- Идемпотентность: `origin_txn_id` + уникальный индекс; при удалении/редактировании источника зеркало обновляется/удаляется.

### 5. Привязка сфер к доменам (domain links) *(owner 2026-07-19)*
Сфера может быть привязана к домену и порождать в нём сущности по проектам/задачам:
- **«Деньги» → Финансы:** проект «Зарплата» + задача «зарплата (имя) 100000» →
  автоматически создаётся **планируемый расход «зарплата»** (в воркспейсе) и, если имя =
  сотрудник-участник, зеркальный **планируемый доход** в личном (см. п.4).
- **«Здоровье» → Трекер привычек:** проект «Похудеть» + задача «Бег» → можно подключить
  привычку «Бег» (привязка task ↔ habit, один клик из карточки задачи).
- **«Карьера» → Воркспейсы:** проект сферы «Карьера» может быть **линком на воркспейс**
  («Бизнес» или воркспейс компании, где я сотрудник, если он есть в системе и я подключён).
  Открытие такого проекта переключает контекст на соответствующий ws (данные ws «дублируются»
  в личный вид через подмешивание, без физического копирования). Модель: `sphere_project_links
  (project_id, link_type ∈ {workspace}, target_workspace_id)`.

### 6. Кросс-доменные связи задач *(owner 2026-07-19)*
- **Multi-link:** задача может быть привязана к **нескольким сферам/проектам**
  (`task_spheres`; N:M к проектам уже есть — `task_projects`)
- **Bidirectional notes/reminders:** заметка/напоминание, созданные из задачи, появляются
  в общих списках «Заметки»/«Напоминания» с бейджем источника; заметка/напоминание, созданные
  из своих меню, могут быть привязаны к задаче/проекту/сфере/ws через каскад-подсказку
  **воркспейс → сфера → проект → задача**. Модель: `note_targets` / `reminder_targets`
  (polymorphic: workspace|sphere|project|task).
- **Календарь:** виды **месяц / неделя / день** (как в iOS), отображение всех доменных
  сущностей с датами (задачи, события, напоминания) + фильтры по воркспейсам и сферам.
- **Трекер привычек:** CRUD (редактирование, удаление), срокhabit'а (start/end date),
  история трекинга.

### WS-15 — Domain links сфер (детали правил автогенерации) *(owner 2026-10-04)*
1. **Сфера «Деньги» → Финансы.** Если у сферы стоит `sphere_domain_links(domain='finance')`:
   - проект «Зарплата» + задача вида «зарплата <Имя> <сумма>» при закрытии/создании порождает
     **планируемый расход** «Зарплата — <Имя>» в контексте воркспейса сферы;
   - если `<Имя>` совпадает с участником ws (email/user), включается зеркало WS-06:
     в личном контексте этого сотрудника появляется «планируемый доход — Зарплата — сумма»;
   - идемпотентность по `origin_task_id`/`origin_txn_id`, при переименовании/удалении задачи
     источник и зеркало обновляются/удаляются каскадно (soft).
2. **Сфера «Здоровье» → Трекер привычек.** `domain='habits'`: из карточки задачи проекта
   («Похудеть» → «Бег») одной кнопкой создаётся/привязывается привычка (`habits.linked_task_id`);
   чекины привычки отражаются как прогресс задачи, но не дублируют её.
3. **Сфера «Карьера» → Воркспейсы.** `domain='workspace'`: проект может быть мостом
   (`sphere_project_links(link_type='workspace', target_workspace_id)`) в существующий ws,
   к которому пользователь подключён (бизнес — свой ws; работа — ws компании).
   Открытие такого проекта = переключение контекста на ws (не копирование данных).
   UI: в списке проектов бейдж «🔗 workspace», вход в экран ws; back — возврат в сферу.

### WS-11 — Multi-link задач
- Задача привязывается к **нескольким** сферам/проектам: N:M к проектам уже есть
  (`task_projects`, миграция 00023 + `EditTaskInput.ProjectIDs`); добавить `task_spheres`
  (N:M к сферам) и FE-мультивыбор. Основная связь сохраняется для обратной совместимости;
  фильтры/календарь/статистика учитывают все связи.

### WS-12 — Bidirectional notes/reminders
- Создал заметку/напоминание из задачи → она в общих списках с бейджем «← задача …» и переходом.
- Создал из меню «Заметки»/«Напоминания» → каскадный picker **воркспейс → сфера → проект → задача**
  (autocomplete, любой уровень опционален); отвязка/смена цели из карточки.

### WS-16 — Настройки главной
- Тогглы видимости и порядок блоков: задачи, трекер, финансы, заметки, календарь, напоминания, долги;
  + выбор, какие воркспейсы подмешивать. Выключенный блок не рендерится и не запрашивает данные.

## Зоны агентов
- **Backend:** миграции, domain-контекст (`ctx workspace_id`), инвайты, фин-синхронизация (use-case FinanceSync).
- **Frontend:** сегменты главной, экран воркспейса, настройки шеринга, переключатель контекста.
- **Telegram:** `/ws <name>` смена контекста, создание задач/трат в текущем контексте.
