# LifeOS — Дорожная карта

**Version:** 0.1
**Status:** Current (synced to code, 2026-10-22)
**См. также:** [ARCHITECTURE.md](ARCHITECTURE.md), [CLIENTS.md](../roadmap/CLIENTS.md)

Дорожная карта описывает, где проект сейчас и что планируется дальше.
Принцип: каждый срез — рабочий продукт для одного пользователя; новые
возможности не ломают Telegram-бот как основной интерфейс.

## Статус по направлениям

| Направление | Статус | Комментарий |
|-------------|--------|-------------|
| Ядро: задачи, проекты, сферы, планирование | ✅ Готово | `internal/tasks`, `projects`, `spheres`, `planning` |
| Финансы, долги, план денежных потоков | ✅ Готово | `internal/finance`, миграции 00008–00009, 00029 |
| Привычки, календарь, заметки, здоровье, карьера | ✅ Готово | отдельные bounded contexts |
| Напоминания и обзоры (встроенный scheduler) | ✅ Готово | [ADR-007](../adr/007-builtin-scheduler.md) |
| REST API + JWT + Mini App | ✅ Готово | `/api/v1`, React 19 |
| Диалоговый агент с tools (LLM) | ✅ Готово (опционально) | `LIFEOS_LLM_ENABLED`, [docs/ai/AGENT.md](../ai/AGENT.md) |
| STT (голосовые) и Vision (фото) | ✅ Готово (опционально) | `internal/ai/stt`, `internal/ai/vision` |
| Память агента и анонимное обучение | ✅ Готово | `internal/memory`, `internal/learning` (opt-in) |
| Десктоп Mac (окно приложения) | 🚧 Бета | тег `desktop-v*`, CI на `macos-14` |

| Webhook вместо polling | 🔣 Частично | `LIFEOS_TELEGRAM_MODE=webhook`, polling остаётся default |
| Мультипользовательский режим / workspaces | 📋 План | следующий крупный этап |
| Redis-кэш, Email/Push нотификаторы | 📋 План | profile `cache`, порты уже определены |
| Полный event sourcing | ❌ Отклонено | оставлены append-only события, [ADR-006](../adr/006-domain-event-log.md) |

## Приоритеты ближайших срезов

1. **UI-чат внутри Mini App.** Чат того же агента есть в десктоп-окне и HTTP;
   в самом Mini App экрана чата пока нет.
2. **Экраны Mini App для существующих tools агента:** карьера, личная память.
3. **Подписанный Windows-инсталлятор** и публикация zip в релизе при
   появлении Windows-раннера в CI.
4. **Workspaces** (мультипользовательские пространства) — не начинать,
   пока не закрыты пункты 1–3.

## Критерии зрелости

| Этап | Что должно быть |
|------|-----------------|
| Alpha (текущий) | один пользователь, локальный запуск, бот + Mini App, MIT |
| Beta | публичный домен, webhook-режим, телеметрия включена по умолчанию |
| 1.0 | мультипользовательский onboarding, миграция данных между воркспейсами, семантическое версионирование API |

Обновления вносются через PR с записью в [CHANGELOG.md](../../CHANGELOG.md);
смена архитектурных направлений требует ADR ([docs/adr/](../adr/README.md)).
